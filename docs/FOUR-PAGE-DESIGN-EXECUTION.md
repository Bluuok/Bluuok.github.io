## 0. 范围与事实基线

本轮仅规划、后续仅改造 `Bluuok/Bluuok.github.io` 作品展示站。不修改 Clawtide 或 ThreadCove 的业务界面、API、权限、模型配置与后端。读取二者的资料只是为了准确描述作品。

已核对作品站 main：`c11dbc9398de2527921ad0b2094b11863d564745`。`src/data/projects.ts` 中只有 Clawtide、ThreadCove 两个占位条目；`src/pages/projects/[id].astro` 当前是共用的基础详情模板。不要把现有占位介绍视为正式产品说明。

已读取的产品事实来源：Clawtide README、`docs/FRONTEND-REDESIGN.md`；ThreadCove README、`docs/FRONTEND-DESIGN.md`。这些是项目自己的文档，并不等于本轮独立完成了产品端到端验证。功能、截图、外链、发布状态在实施时还要绑定版本核验。

### 决策锁定

| 项目 | 决策 |
| --- | --- |
| 页面数 | 四个主要路由，不再单独创建第五个 First Spark 页面 |
| 首页 | 首屏保留现有粒子；下一段增加风驱动的可变形三维布料 |
| 作品页 | Clawtide 与 ThreadCove 各有独立叙事与构图，不是换色模板 |
| 小项目页 | 所有其余真实小项目与实验；First Spark 在此页内按需展开 |
| 全站外壳 | 保留冷白、深灰、局部蓝紫粉、留白、清晰文字 |
| 真实界面 | 截图保持产品本来的配色；不为了统一作品站而重绘截图 |
| 三维布料 | 正式高质量版本必须有实际三维几何与形变，二维视差仅作原型/降级 |
| 动效职责 | 首页建立气氛；项目页解释内容；实验页容纳更强交互 |
| 正文优先 | 页面与链接不依赖三维资源加载完成；不要求看完动画才能看作品 |

以下尺寸、时间、数量、资源预算均为设计与工程起点，不是已验证的性能承诺。

## 1. 信息架构与导航

```text
/                             首页
/projects/clawtide/            核心项目：Clawtide
/projects/threadcove/          核心项目：ThreadCove
/playground/                   小作品与实验
  #first-spark                 《创造亚当 / First Spark》页内体验
```

保留现有两个核心项目 URL。`/playground/#first-spark` 是第四页的一个状态，不是第五个页面。关于、联系方式仍放首页末尾，不新增 About/Contact 路由。

全局导航建议：品牌首页链接；精选作品（`/#projects`）；小作品与实验（`/playground/`）；关于（`/#about`）；GitHub 外链。移动端折叠导航仍用普通链接。当前页用文本/下划线提示，不使用只靠颜色的状态。

项目页增加局部章节导航：概览 / 界面 / 工作方式 / 工程取舍。首屏同时提供“看真实界面”和“查看源码”，不把访客困在艺术主视觉里。页尾互链另一个核心项目，并提供返回首页作品区。

站点路径通过同一 URL helper 结合 `import.meta.env.BASE_URL` 生成。首页锚点与当前页锚点分开；当前页跳过导航链接始终指向本页 `main`。所有锚点为固定头部设置滚动偏移。

第一阶段保留普通多页面导航。跨文档 View Transitions 仅作为兼容性允许时的渐进增强，不把转换成 SPA 作为四页设计的前提。

## 2. 统一视觉系统

### 2.1 保留现有外壳

沿用 `src/styles/tokens.css`：

| 角色 | 当前值 |
| --- | --- |
| 背景 | `#fafbfc` |
| 表面 | `#fff` |
| 正文 | `#24262b` |
| 辅助文字 | `#6a6e79` |
| 分隔线 | `#e4e6ec` |
| 蓝 / 紫 / 粉 | `#537ce9` / `#9371de` / `#cd8fba` |
| 内容最大宽度 | `1280px` |
| 页面留白 | `clamp(24px, 5.5vw, 100px)` |

配色不大改；发光不能成为正文文字的唯一载体。装饰细线与功能性边界分开。文字和按钮保留 DOM，不烘焙进图片/Canvas。

排版建议：正文 16–18px；说明 13–14px；首页大标题桌面约 64–88px、手机约 36–48px，具体由现有文案长度调整；不要照搬当前装饰性 9px 标签来承载重要功能信息。正文行长约 36–42 个汉字。大章节垂直间距桌面 96–144px、手机 64–88px。核心项目页可采用 12 栏网格，但不让正文过宽。

### 2.2 四页区别

| 页面 | 视觉主题 | 材质 | 主要运动 | 结构性构图 |
| --- | --- | --- | --- | --- |
| 首页 | 光尘 → 风 → 作品 | 细粒、白色纤维布料 | 扩散、局部凹陷、缓慢复位 | 居中首屏 → 非对称布料 → 两项作品 |
| Clawtide | 潮汐中的秩序 | 冷白哑光陶瓷、浅刻槽 | 沿路径传播、层次照明 | 左文右装置 → 大界面 → 横向机制 |
| ThreadCove | 线索的编织 | 雾蓝纸面、半透明纸页、细线 | 展开、关联高亮、对齐 | 档案式页眉 → 宽研究台 → 纵向案例 |
| 小项目页 | 开放的工作室 | 统一展签、多样封面 | 局部预览、主动体验 | 分类索引 → 松紧有序的画廊 → 页内展开 |

不要用首页布料复制两遍做两个项目页。Clawtide 与 ThreadCove 的差异来自结构、材质、节奏、说明方式四个维度，而不仅是强调色。

真实产品 UI 保持原貌：Clawtide 文档确认暖象牙、森林绿、青绿色及潮汐艺术；ThreadCove 当前是 FIELDNOTES LAB / 研究图谱，雾蓝灰蓝，不应再拿已被替代的森林绿方案来当其现状。外层展示站依旧冷白，产品自己的颜色限制在真实截图/录像及少量明确的品牌标识内。

## 3. 首页：先认识作者，再触碰材料，最后进入作品

### H1. 粒子首屏 / Light in Motion

高度目标约 100svh，以实际内容可容纳为准；不做长时间钉定。保持现有居中大标题、简介、真实作品入口、冷白背景和粒子气氛。

将 ParticleField 从 Intro 中独立接到首页新 Hero。以当前版本截图作为基线，首轮不同时改变粒子数量、颜色、半径与绘制算法。继续保留其常态、辉光、局部鼠标响应，原星芒/字符聚形可以继续存在。移走的是与双手绑定的后段汇聚与曝光，而不是整套粒子。

首屏主按钮“查看精选作品”直达 `#projects`；次入口“小作品与实验”。只想了解项目的访客可以直接跳过布料。移动端也不能因为装饰画面把主按钮挤到不可见区域。

首页粒子实例使用 ambient 场景模式；First Spark 的实例使用 intro 场景模式。两者共享实现，不共享运行时状态。首页不能在一个与双手无关的全页滚动阈值上突然聚成光球。

### H1 → H2. 转场：看见风，而不是烟花式变形

不使用全屏闪白，不让所有粒子硬拼成布料网格。首屏退出时，局部粒子沿同一风向稍微拉开，密度/可见度自然降低；下一段的布料以相同光向和速度接续。

这是一种视觉连续性，不宣称是同一批三维粒子变成织物。两个区块可以分别渲染，避免为无必要的拓扑转换引入复杂算法。

### H2. 风的形状 / Fabric of Thought

这是正式的首页艺术记忆点。不是三张漂移图片，也不是商业网站常见的彩虹胶带。

主物体是一幅宽而不规则的冷白纤维薄布：有一处明确折脊、一处下垂凹面、一条可辨识自由边。整体像展厅中的轻型纺织装置，而不是日常窗帘、床单或旗帜。大部分表面哑光乳白，蓝紫粉仅沿少数边缘或折面掠过。相机近乎正交、轻微俯视，保持克制的厚度与可信阴影。

桌面布料占该段右侧约 55%–65%，文案在左侧安静区域，不压在褶皱上。仅建议一句主题文案，例如“让想法，拥有形状。”，再一行实际作者说明；文案是创作提案，不是产品能力宣称。区块总高度约 110–130svh，其中仅有很短的 sticky 展示余量；手机不钉定。项目入口目标不晚于首屏后约 2.5 个视口，具体检查不同高度设备。

#### 局部交互

| 输入 | 反馈 | 禁止 |
| --- | --- | --- |
| 静止 | 有限、极慢的自然起伏，默认形态仍完整 | 没有鼠标就塌成一块、持续大摆动 |
| 鼠标靠近 | 局部受力区域轻微下陷，周围折面跟随 | 整块平移追光标 |
| 掠过 | 凹陷沿移动方向带少量惯性；少量边缘微粒响应 | 全屏波纹、喷射彩屑 |
| 离开 | 约 0.7–1.2s 平滑复位，参数实测调优 | 一直振荡或瞬间跳回 |
| 滚动 | 外层构图轻微侧转、让位于下一节 | 强制拖拽才能继续浏览 |
| 进入文字/按钮 | 不再向布料注入新作用力 | 按钮被牵动、文字折射变形 |

正式材质与几何技术见第 8 节。首版最多一个主布料，不叠三块高成本透射材质。光尘在本段降为陪衬，不继续铺满整个视口。

### H3. 两个精选项目 / Selected Work

顺序固定 Clawtide、ThreadCove。桌面采用两个足够宽的项目单元（或两行交错图文，素材长度决定），手机纵向排列，不做小九宫格。

每项有：真实名称、基于核实资料的一句话定位、真实界面缩略图、最多三个可靠关键词、详情链接和可用源码链接。艺术封面只能作为局部引导，不能替代真实界面证据。两项的装置缩略图分别呼应“潮汐刻槽”和“线索纸页”，页面过渡时可使用同一张静态封面作为共享视觉元素，不共享正在运行的 WebGL 实例。

悬停仅小幅浮起与图片内部视差，文字和点击范围固定。无需轮播才能看到第二个核心项目。

### H4. 小作品入口

取真实目录中 3–4 个代表项做简短索引，包含 First Spark。总数根据目录真实计算，不写虚构数字。入口标签“小作品与实验”，不要用“杂项”降低呈现质量。

### H5. 关于与联系

简短作者介绍、真实关注方向、GitHub、已核实联系渠道。不造履历、客户、成绩或合作数据。这里是安静收尾，不再循环背景动画。

## 4. Clawtide 项目页：潮汐中的秩序

### 事实支点

按当前 README，它是自托管、多用户的 AI 数字员工平台，包含 Web、IM、定时任务入口及工作区/身份/权限管理。README 明确区分 Telegram/飞书与其他骨架渠道，不能宣传“七大平台已全部接通”。产品文档还区分了 fixture 验证和真实模型执行，不将二者混淆。

### C1. 左文右装置的概览

左侧占约 40%–45%，显示项目名、一句话定位、三个已核实关键词、“看真实界面”和“查看源码”。右侧是一件冷白陶瓷潮汐装置：三道低矮弧形构件，表面有精细沟槽，构成有序而非混乱的浅波。

三道路线只作为 Web / IM / 定时任务三个入口的视觉隐喻，并配 HTML 标签说明。它不是系统实时拓扑，不显示虚构在线数字。

鼠标改变小范围光位/观察角，物体保持刚性；不要像布料一样变形。选择某一入口标签时，对应沟槽光线走一次，下方说明切换。鼠标悬停仅预览，不导致内容频繁跳动；键盘与点击可以固定选择。

### C2. 真实界面是主证据

紧随概览给出一个大幅真实界面展示，保持暖象牙、森林绿的原 UI。可用有明确标签的三组截图/短录像：工作区/会话；任务与运行记录；角色与配置。最终取材以当前可运行版本为准。

每张图附一句“这张图具体说明什么”。交互回放若使用本地脚本数据，必须标“示意回放”；不要在静态作品站中真的替访客发送消息或执行模型任务。没有公开演示地址则不显示“在线体验”。

### C3. 一条任务如何进入运行时

用可点击 SVG/DOM 路径做精简机制说明，而不是巨型系统架构海报：

```text
Web / IM / 定时触发
      ↓
相应入口的鉴权、归属与上下文决策
      ↓
工作区 / 会话 / 执行路径
      ↓
运行、状态记录与反馈
```

具体术语由代码核实，不把三个入口画成鉴权流程完全一致。默认全部文字可读；点击阶段只增加说明和局部高亮。不要强制逐步播放才能阅读后续。

### C4. 三个工程取舍

建议围绕任务生命周期、上下文与角色边界、渠道能力边界分别写一小节。每节绑定一张真实界面或可核查的源码/文档入口。承认项目适用范围，不使用“企业级高可用、零故障、自动完成一切”等无依据文案。

### C5. 上手、边界、下一项

展示真实启动文档链接、当前版本标识、环境与密钥前提、已知未完成部分。保留 upstream / license 归属信息。页尾提供 ThreadCove、返回作品区。

整体情绪：稳定、精确、有节奏，不是游戏控制台或黑色监控大屏。

## 5. ThreadCove 项目页：线索的编织

### 事实支点

按当前 README，它面向个人深度研究，组织独立研究任务、多个 Agent 后端和统一事件流，Electron 与 Web 复用传输协议。当前前端设计文档采用 FIELDNOTES LAB / 研究图谱、雾蓝工作纸面。不能把它描述成企业级多用户系统，也不能把展示动画说成已实现的自动知识图谱或自动事实核验功能。

### T1. 档案式页眉与线索纸页

不复用 Clawtide 的左文右雕塑模板。使用上方大标题/摘要与右侧短元信息，下方为横向展开的“研究台”：几张薄纸页、有限细线、少量批注标记。浅雾蓝只占局部纸面，外层背景仍冷白。

纸页可代表“问题”“任务”“材料”“输出”的展示阶段，但明确是概念示意，不使用看似真实但虚构的引用条目。鼠标靠近某一页，关联线略收紧、相关纸页显清晰；选择标签后固定解释。没有鼠标时，默认关系依然可理解。

实现优先 DOM + SVG + 轻量 2.5D，读取内容保持 HTML。这里不需要第二套布料物理，也不需要强行导入 Three.js。

### T2. 真实 FIELDNOTES 工作台

给宽幅真实截图，让档案式任务索引、研究画布、对话区与输入区可见。保持当前雾蓝灰蓝 UI，不还原已经淘汰的森林绿版本。点击局部注解时只放大现有图像的对应位置或展开说明，不能用 AI 重绘不存在的界面。

优先准备：任务索引/初始研究画布；真实对话与流式事件；来源/任务设置等已核实关联流程。需要录屏时使用不含私人资料的演示工作区，注明取材版本与日期。

### T3. 一次研究的叙事

用真实可复现的小研究样例呈现：提出问题 → 建立任务/选择后端 → 工具和事件过程 → 阅读已有产物。哪些是用户手动操作、哪些是系统自动执行必须准确。

内容采用纵向展开的纸页与注解，不做高频自动轮播。桌面可让章节导航短暂 sticky，正文继续普通滚动；手机全改垂直顺序。

### T4. 工程深度

主讲三个与 Clawtide 不同的点：任务隔离；后端事件归一；桌面/Web 通道分类。每点由简洁机制图、真实文件入口和限制说明支撑。不要复制 Clawtide 的“角色/多用户治理”内容。

例如可以用三条输入轨道汇入统一事件输出的轻量图，但仅表达接口适配；不能暗示所有后端能力完全相同。

### T5. 适用场景与边界

说明个人研究工作台的适用对象、运行要求、已验证/待验证路径、源码与文档入口。README 中的测试数、模型可用性等易变字段不硬编码成营销数字。页尾返回 Clawtide 或作品总览。

整体情绪：好奇、细致、可阅读，像工作中的研究手稿，而不是另一个控制台。

## 6. 小作品与实验页：开放工作室

### P1. 标题与索引

页面名“小作品与实验 / Playground”。短说明后直接给真实分类，例如工具、视觉实验、交互原型；分类基于已有项目，不创建空分类凑数量。

所有条目先服务端/静态输出。JS 增强分类/搜索，关闭 JS 仍能浏览。筛选状态可用查询参数保存；First Spark 用固定 hash 定位。不让每次悬停都写入浏览器历史。

### P2. 有编辑节奏的画廊

不是无限漂浮、也不是每个卡片同时播放 Canvas。桌面让一个精选实验宽一些，其余正常网格；DOM 顺序与视觉顺序一致。手机为单列。条目多时采用可访问的“展开更多”或普通分页，避免必须滚动无限流才能返回页脚。

每项含真实名称、类型、状态、短说明、封面、源码/演示入口。原型、实验、已发布工具使用不同文字标记。不从仓库名称猜测功能或正式上线状态。

### P3. First Spark 的页内体验

默认是一张静态纸手海报、简述与“开始体验”按钮。点击后在原卡片位置展开全宽舞台，URL 更新为 `#first-spark`；有“结束体验 / 返回列表”“重播”。不新增 `/lab/first-spark/`，不创建另一个浏览路由。

展开后才加载旧双手资源、旧序章脚本和对应粒子场。保留原手图、锚点、接触点、滚动正反向、柔光与曝光；只把首页文案换成作品标题/介绍。原来指向首页 sections 的链接改为明确传入的页内结束/返回链接。

原 Intro 的选择器、ScrollTrigger ID、CSS 与事件作用域需实例化，不能继续依靠整个 document 唯一的 `[data-intro]`。舞台展开并完成布局后 refresh，结束时 kill/revert 自己的时间轴、移除 pin spacer、停止粒子、清理资源；回到入口并恢复焦点。不把 body 长期锁滚动。

直接访问 hash 时，应能定位并展开或给出明确开始控件；无 JS 时仍显示海报和说明。关闭体验不能跳到页面顶端或留下数屏空白。浏览器后退从 hash 回到列表状态时也要正确销毁。

若保留旧版较长滚动叙事，它只出现在用户主动展开之后；小项目列表默认没有数屏的强制开场。

### P4. 其他项目

轻量项目内联预览；真正的应用使用真实外链。与 First Spark 采用相同的加载/销毁契约，同时只运行一个主动实验。只有首个已核实实验时就只展示它，不杜撰剩余条目。

## 8. 布料技术路线与素材交付

### 8.1 选择的正式路线

采用真实三维网格 + 少量预制形变状态/动画 + 局部实时扰动。推荐先用 Three.js WebGL 渲染器，延迟加载；不以 WebGPU、完整刚柔体物理引擎或 React Three Fiber 作为默认依赖。

Lusion 2019 制作方案例的核心方法是预计算不同拖拽方向，再根据输入混合并加实时失真。这支持“预计算 + 实时响应”的路线，但不是现成可复制素材，也不保证我们的文件大小或画质与其一致。

初版只需要有限相机角度，不开放自由环绕；若开放自由相机，后侧材质、拓扑、灯光和碰撞要求会明显扩大，应另立范围。

### 8.2 素材包

建议交付（文件名是目标约定，不代表已存在）：

- 布料源文件：Blender/Houdini/等价 DCC 工程，保留材质和相机。
- 渲染网格：稳定 UV、正确法线、干净三角面；初始约 2k–5k 顶点/对应低模档，最终按测试决定。
- 基础姿态 + 至少四个方向的受力状态，顶点数量/顺序和拓扑完全一致。
- 同步的法线处理方案；不能只移动位置而保留不匹配的光照。
- 纤维 normal/roughness 等纹理与许可记录；不把 AI 图片自动视为准确的法线、高度数据。
- 一张静态 poster，构图与默认三维场景一致，作为未加载/失败/低动态回退。

静态效果图只审批美术方向，不能替代真实网格的验收。二维图片 transform 是过渡原型，不标记为正式三维交付。

### 8.3 变形与材质

指针先转换为场景局部坐标，命中布料上的区域，再以距离衰减确定扰动。预制方向权重非负且归一，状态切换用阻尼平滑。局部扰动也要有固定受力范围和最大幅度，不应把同一整体 morph 当作任意位置都能真实下陷的证明。

更稳妥的组合是：预制形态负责大褶皱与轮廓；局部解析/着色器扰动负责鼠标附近的小凹陷；正确重算/混合法线负责受光。没有自碰撞、撕裂、布料任意抓取的需求，因此不宣称完整物理模拟。

材质优先粗糙度、细纤维法线、适量 sheen；虹彩只有边缘与特定折面。首版不叠满屏强透射、实时折射、重后期 Bloom 和多盏动态阴影灯。`MeshPhysicalMaterial` 可以表达 sheen/iridescence，但启用这些效果有额外成本，要按测试做取舍。

## 9. 动画与生命周期契约

### 9.1 三类输入分工

- 时间：仅控制轻微自然运动。
- 指针：仅控制当前区块的局部扰动。
- 滚动：控制该区块的构图、显隐和进入/退出。

不要让三个来源同时修改同一个 transform 或 shader uniform。建议外层处理章节/滚动，中层处理有限姿态，网格或内层处理局部形变。每个场景自己的 progress 是 0–1，不共用整站总进度。

### 9.2 最小控制器约定

```ts
// 设计接口示意，非完整实现。
interface SceneController {
  start(): void;
  pause(): void;
  resize(width: number, height: number, dpr: number): void;
  setProgress(progress: number): void;
  dispose(): void;
}
```

组件可内部拥有状态；共享的是输入规范、质量策略与生命周期，不是把粒子、布料、研究线条硬塞进同一渲染器。各类动画明确调度所有权；不要同时用多个 ticker/rAF 更新同一场景。

### 9.3 加载、恢复与销毁

每个场景至少区分 poster、loading、active、paused、fallback、disposed。接近视口时才加载重资源；初始化失败保持 poster，允许轻量重试，不挡正文。

首页只在 H1 激活粒子；H2 激活布料时让前一个大场景暂停，短暂交接除外。Clawtide 页只加载其装置，ThreadCove 页默认不加载三维库。实验页只有主动进入的实验加载运行资源。

离屏/后台暂停；恢复时重置时间基线，限制 delta，避免后台返回后形变暴冲。`pointercancel`、移出、失焦、结束体验、降低动态偏好都清除指针受力。

Resize 不要每次重新随机生成全部粒子导致闪跳；手机浏览器地址栏变化也不能频繁销毁重建布料。实际尺寸稳定后更新投影与渲染目标。

普通 MPA 首次加载和 `pageshow/pagehide` 的缓存恢复要覆盖；将来若启用 Astro ClientRouter，再增加相应路由生命周期初始化/销毁，不能假定只监听一次 DOMContentLoaded 就够。

销毁时释放本场景的几何体、材质、纹理、render target、观察器、事件、补间和循环；共享资源按明确所有权处理。停止 rAF 或移出 DOM 不等于释放 GPU 资源。

## 10. 性能、移动端与无障碍

### 10.1 工程目标，不是既得指标

| 项目 | 建议目标 |
| --- | --- |
| 首屏 | HTML 与按钮先可用；不等待三维素材；不预加载全站模型 |
| 布料包 | 渐进加载，含初次所需引擎/网格/纹理的压缩传输量目标约 1.5–2MB 内；超预算先优化而非阻塞首页 |
| DPR | 初始上限 1.5；低质量档可降至 1；按画质/设备测试决定 |
| 活跃场景 | 同一可见阶段最多一个高质量主视觉，交接短时例外 |
| 动画 | 目标平滑接近设备可承受刷新率；记录中位数与 P95，不仅平均 FPS |
| 质量降级 | 先减后期、阴影、分辨率，再减次要效果，最后静态 poster |
| CWV | 面向真实用户 P75：LCP≤2.5s、INP≤200ms、CLS≤0.1；发布前实验室测试不是已达到现场指标的证据 |

不要用“Lighthouse 分数高”替代连续拖拽、滚动和实验关闭重开的检测。纯导航 Lighthouse 运行也不能直接证明 INP。

### 10.2 触屏

手机保留网页纵向滚动和缩放。布料默认低动态或静态构图，点击局部可有短响应，但无需模拟桌面 hover。不要在整页设置 `touch-action:none`；需要局部手势时仍允许纵向平移与缩放，并正确处理被浏览器取消的指针。

项目页的路径/线索高亮有点击与键盘等价入口。实验播放器有可见的开始、暂停/结束、重播，不让手势成为唯一控制方式。

### 10.3 减少动态效果与暂停

初始/运行时 `prefers-reduced-motion` 都要得到完整的静态形态：粒子固定、布料固定在批准姿态、无钉定缩放、无白化闪光。不是停在上一次变形最严重的瞬间。

持续非必要动画增加可发现的“动态效果开/关”控制；关闭后记住本地偏好，系统减少动态效果优先。点击效果关闭不影响内容。

每页唯一 H1；导航与按钮有可见焦点；内容顺序无需视觉效果才能理解；装饰 Canvas 为 `aria-hidden`，所有必要解释在 HTML。没有透明/不可见但仍可聚焦的按钮。章节跳转后标题不被固定导航遮挡。

## 11. 分阶段 PR 与验收门槛

PR 按可独立审查的职责拆，不把七个编号理解为七次强制合并。测试跟随每个 PR，而非最后再补。

### PR-01 — 四页路由、数据与导航骨架

目标：四个路由、两个 case 变体、公共导航、正确锚点、项目/实验数据区分、关闭功能后的完整正文。保留粒子与旧 Intro 的源文件，不急着替换美术。

改动入口：pages/index、pages/projects/[id]、新 playground；Header/Layout；data/projects 与 experiments；config/features；URL helper。

验收：四页构建；直接访问/刷新/返回；空 sections；删除/关闭项目后的返回入口；没有新的第五页面；不修改两个产品仓库。

### PR-02 — 静态美术系统与媒体证据

目标：四页关键构图先成立。审批首页粒子基线、布料静止姿态、Clawtide 陶瓷装置、ThreadCove 档案纸页、实验列表。采集两项目真实截图，完成媒体类型与说明。

交付：四页桌面/手机静态稿；布料 source/mesh/poster；产品事实-媒体-版本对照表；字体/颜色/间距规范。

验收：未加载 JS 仍完整；文字不烘焙；截图和概念图标识准确；两产品不是换色模板。此门未通过前，不用复杂动效掩盖构图问题。

### PR-03 — 首页粒子解耦与风布料

目标：现有粒子独立成为首页 H1；H2 按方案接入真实网格和有限形变；两段交接；首屏直接跳作品。

验收：与批准粒子基线对照；粒子不会跟双手阶段错误汇聚；布料命中位置与局部凹陷一致；三维法线随形变正确；快速倒滚、鼠标移出、后台恢复不暴冲；低动态正确静态化。

### PR-04 — Clawtide 定制项目页

目标：独立概览、陶瓷装置/轻交互、真实 UI、三入口说明、工程取舍与限制。

验收：首屏直接看界面/源码；渠道能力不夸大；演示/截图有标签；没有强制观看的长开场；保留真实产品配色；无在线数据假象。

### PR-05 — ThreadCove 定制项目页

目标：档案构图、研究线索交互、真实 FIELDNOTES UI、真实研究样例、独立工程说明。

验收：内容与 Clawtide 显著不同；DOM 可读/选中；不虚构自动知识图谱、准确率和企业能力；未引入不必要的三维依赖；移动阅读顺畅。

### PR-06 — 小作品目录与 First Spark 搬迁

目标：真实目录筛选、静态封面、按需体验、hash/历史/返回焦点；保留原素材与锚点。

验收：首页网络请求不包含手图/旧时间轴；实验关闭后无 pin spacer；开关往返十次无观察器和 GPU/Canvas 实例持续增长；直接 hash 与无 JS 可用；一次只运行一个实验。

### PR-07 — 跨页性能、恢复与视觉回归

目标：质量档、页面往返、资源释放、移动端、低动态、键盘、截图与性能记录完整。

验收：打包与类型检查通过不作为唯一证据。至少测试桌面 1440×1000、紧凑窗口 1280×720、手机 390×844；条件允许覆盖真实 Windows Chromium、真实 Android Chrome 和 iOS Safari。未执行的平台明确标未验证。
