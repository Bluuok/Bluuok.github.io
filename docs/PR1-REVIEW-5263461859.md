## 实现与修改入口

- `src/features/cloth/pose.ts`、`baked-poses.json`、`scripts/bake-cloth-rest.mjs`：构建/dev 启动自动校验五份初始姿态。配置哈希包括尺寸、拓扑、物理参数和 solverVersion。约束长度仍来自原始材料网格；加载姿态只恢复位置、初始状态和零速度。修改 solver 算法时递增 solverVersion。缺失/无效姿态走每 6 步一次真正 task yield 的准备流程，不展示平面塌落。
- `cloth/controller.ts`：首页提前 800px 准备、Cove 提前 250px，独立可见性激活。共享模块 Promise；每 renderer 独立 PMREM。场景、贴图、相机完成后 compileAsync、上传纹理、预绘制，再启用交互。所有异步准备受取消/上下文状态保护；离屏和后台停止物理 RAF。
- `cloth/spatial-hash.ts`、`solver.ts`：复用整数缓冲、精确格子过滤、拓扑邻居排除、跨布片 AABB 粗筛。controller 统一 120Hz 固定步长，跨片修正后重建速度。仍为离散粒子厚度近似，不是连续三角面碰撞。
- `cloth/surface.ts`：预计算 bicubic 采样索引与权重，独立侧面顶点和切线法线；不再每帧计算整个高精网格包围球。低精变形代理负责拾取，pointermove 每帧消费一次，down/up 保留准确点击判定。
- `cloth/material.ts`：四份基础文字纹理取代八份选中/未选中纹理，选中框由 uniform 控制。桌面 768×1152，手机 384×576；材质、颜色和内容数据仍各自独立。
- `first-spark/story.ts`、`particles/field.ts`：所有可见彩点从起始阶段移动，主流 .58 收束、尾流 .70 收束，终点位于真实指尖周围 7px 内，接近终点即吸收而不叠成光球。无固定 ambient 分支；setScene 只更新输入，单 RAF 绘制。倒滚由进度直接求解。
- `particles/home-flow.ts`：位置积分低频背景流与局部冲量，默认自由模式不再追赶 home。最多 64 个 coalesced 带时间戳样本、每段仅消费一次、指数衰减、边界渐隐回收。默认半径 160px、半衰期 .42s、冲量上限 260px/s；短拖尾只在快粒子上出现。
- `lib/scene-readiness.ts`：仅 `?scenePerf=1` 启用本地 Performance 标记、构建版本和采样入口；无网络采集。资源传输使用 Resource Timing transferSize。

## 性能口径

Node 构造器计时是同步 CPU 耗时；浏览器阶段标记是主线程观察的经过时间，不是纯 GPU 执行时间。屏幕首帧记录默认 framebuffer 上的首次提交，排除 PMREM 的离屏预处理；并非操作系统呈现时间。

同机 Chromium 140.0.7339.16 / SwiftShader，1440×1000、DPR 1、正常动态效果。每场景 fresh-context 与同 context 再导航各三次，每次 10 秒交互。静态 HTTP 未压缩、未强制缓存；warm 只是重复导航标签，实际命中以 transferSize 为准，不以资源文件大小冒充网络成本。

物理手机 GPU、Safari、线上真实网络未测。Three.js 大 chunk 警告仍在；不宣称所有设备 60fps 或所有冷启动都小于 150ms。

### 结论与未达标项

- 冷启动主 framebuffer 首次提交：首页 2425→676.5ms（约 72% 降幅），Cove 1107.2→271.7ms（约 75%）。准备、环境和文字完成后再交互。
- 构造器中位数：首页 378.0→0.73ms，Cove 四份合计 924.0→1.48ms。这里不包含模块下载/解析、纹理、显示几何、GPU 初始化，不把它冒充整个初始化 CPU。
- 物理步 p50：首页 2.103→1.110ms，Cove 四份合计 5.264→2.884ms，分别约下降 47% 和 45%。独立 solver 测量不包含跨片粗筛、显示表面和渲染器。
- **持续帧率目标未在当前环境达成。** 首页 p50 仍为 200ms，Cove p50 从 183.3ms 到 199.9ms；Cove p95 有改善，不能据此称整体持续帧率提升。约 150ms 滚入目标也未稳定达成。
- 默认无额外 flags 的 headless 通路同样报告 SwiftShader；硬件 WebGL 路径未验证。当前保留完整材质和粒子数量，不以降低画质后的不同场景作为对比数据。
- 每页 transferSize 增量与姿态数据/小模块有关；warm 大多仍实际传输。首屏大 Three bundle 仍是可继续优化项，本轮没有引入更大 GPU 粒子引擎。
- 计时在 dd32262 的修改后工作树上采集，浏览器 readiness 记录 dd32262-dirty，资源文件哈希在原始数据中。原基线来自 dd32262 独立归档构建。最初误包含 PMREM 提交的尝试数据未用于表格。
